# API Design Principles: Building Better APIs

A well-designed API is crucial for building scalable applications. Let's explore the key principles.

## RESTful Architecture

REST (Representational State Transfer) is the most common API style:

```
GET    /api/posts          # List all posts
GET    /api/posts/:id      # Get single post
POST   /api/posts          # Create new post
PUT    /api/posts/:id      # Update post
DELETE /api/posts/:id      # Delete post
```

## Request/Response Format

### Request Example

```json
{
  "title": "My First Blog Post",
  "description": "A brief description",
  "content": "Post content here",
  "tags": ["web", "api", "design"]
}
```

### Response Example

```json
{
  "id": "abc123",
  "title": "My First Blog Post",
  "description": "A brief description",
  "content": "Post content here",
  "tags": ["web", "api", "design"],
  "createdAt": "2024-05-08T10:30:00Z",
  "updatedAt": "2024-05-08T10:30:00Z"
}
```

## HTTP Status Codes

| Code | Meaning | Use Case |
|------|---------|----------|
| 200 | OK | Successful request |
| 201 | Created | Resource created |
| 204 | No Content | Success, no response body |
| 400 | Bad Request | Invalid input |
| 401 | Unauthorized | Authentication required |
| 403 | Forbidden | Access denied |
| 404 | Not Found | Resource doesn't exist |
| 500 | Server Error | Internal server error |

## Versioning Strategy

### URL Path Versioning

```
GET /api/v1/posts
GET /api/v2/posts
```

### Header Versioning

```
GET /api/posts
Accept-Version: 1.0
```

## Error Handling

Always provide consistent error responses:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request",
    "details": [
      {
        "field": "email",
        "message": "Invalid email format"
      }
    ]
  }
}
```

## Best Practices

1. **Use meaningful HTTP methods**
   - GET for retrieval
   - POST for creation
   - PUT for updates
   - DELETE for deletion

2. **Implement pagination**
   ```
   GET /api/posts?page=1&limit=10
   ```

3. **Use consistent naming**
   - Use kebab-case for URLs: `/api/blog-posts`
   - Use snake_case for JSON: `{"created_at": "..."}` OR camelCase: `{"createdAt": "..."}`

4. **Document your API**
   - Use OpenAPI/Swagger
   - Provide clear examples
   - Document all endpoints

5. **Secure your API**
   - Use HTTPS
   - Implement authentication
   - Rate limiting
   - Input validation

## API Documentation Example

