Docker revolutionizes how applications are deployed. Let's explore containerization essentials.

## What is Docker?

Docker packages your application and all its dependencies into a container, ensuring it runs the same everywhere.

```
┌─────────────────────────┐
│   Docker Container      │
│  ┌─────────────────┐   │
│  │   Application   │   │
│  ├─────────────────┤   │
│  │  Dependencies   │   │
│  ├─────────────────┤   │
│  │   Runtime       │   │
│  └─────────────────┘   │
└─────────────────────────┘
```

## Dockerfile

Define your application environment:

```dockerfile
# Use official Node.js runtime
FROM node:18-alpine

# Set working directory
WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm ci

# Copy application code
COPY . .

# Expose port
EXPOSE 3000

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD node healthcheck.js

# Start application
CMD ["npm", "start"]
```

## Docker Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `docker build` | Build image | `docker build -t myapp:1.0 .` |
| `docker run` | Run container | `docker run -p 3000:3000 myapp:1.0` |
| `docker ps` | List containers | `docker ps -a` |
| `docker logs` | View logs | `docker logs container-id` |
| `docker stop` | Stop container | `docker stop container-id` |
| `docker push` | Push to registry | `docker push myapp:1.0` |

## Multi-Stage Build

Optimize image size with multi-stage builds:

```dockerfile
# Build stage
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Runtime stage
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY --from=builder /app/dist ./dist
EXPOSE 3000
CMD ["npm", "start"]
```

## Docker Compose

Manage multi-container applications:

```yaml
version: '3.8'

services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgresql://db:5432/myapp
    depends_on:
      - db
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  db:
    image: postgres:15-alpine
    environment:
      - POSTGRES_DB=myapp
      - POSTGRES_PASSWORD=secret
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:
```

## Best Practices

1. **Use Official Base Images**
   ```dockerfile
   FROM node:18-alpine  # ✅ Official image
   FROM random/node     # ❌ Unofficial
   ```

2. **Keep Images Small**
   - Use `.dockerignore` to exclude unnecessary files
   - Use alpine variants when possible

3. **Use Non-Root User**
   ```dockerfile
   RUN useradd -m appuser
   USER appuser
   ```

4. **Pin Dependency Versions**
   ```dockerfile
   RUN npm install express@4.18.2  # ✅ Specific
   RUN npm install express         # ❌ Latest
   ```

5. **Leverage Layer Caching**
   ```dockerfile
   # Put frequently changing layers last
   COPY . .           # Changes often
   RUN npm install    # Rarely changes, cache this
   ```

## Common Docker Workflows

### Development

```bash
# Build image
docker build -t myapp:dev .

# Run with volume mount for live reload
docker run -p 3000:3000 \
  -v $(pwd):/app \
  myapp:dev
```

### Production

```bash
# Build with specific tag
docker build -t myapp:1.0.0 .

# Push to registry
docker push myrepo/myapp:1.0.0

# Deploy
docker run -d \
  --name myapp \
  -p 80:3000 \
  myrepo/myapp:1.0.0
```
