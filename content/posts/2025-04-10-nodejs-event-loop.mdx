# Understanding Node.js Event Loop

The event loop is the heart of Node.js. Understanding it is critical for performance.

## Event Loop Phases

```
┌─────────────┐
│  timers     │ - setTimeout, setInterval
├─────────────┤
│  pending    │ - I/O operations
├─────────────┤
│  idle       │ - Internal
├─────────────┤
│  poll       │ - Accept connections
├─────────────┤
│  check      │ - setImmediate
├─────────────┤
│  close      │ - Cleanup
└─────────────┘
```

## Blocking vs Non-Blocking

```javascript
// ❌ Blocking - Freezes event loop
const data = fs.readFileSync('file.txt');

// ✅ Non-blocking - Continues processing
fs.readFile('file.txt', (err, data) => {
  // Handle data
});

// ✅ Better - Using promises
const data = await fs.promises.readFile('file.txt');
```

## Best Practices

- Use async/await
- Avoid synchronous operations
- Use worker threads for CPU-intensive tasks
- Monitor event loop lag
